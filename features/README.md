# 功能目录

每个功能使用独立目录，功能之间只通过官方消息接口、身份映射和统一配置交互。

| 目录 | 当前状态 | 说明 |
| --- | --- | --- |
| `basic_commands` | 已实现 | 基础指令、状态和功能菜单。 |
| `identity` | 已实现 | 显示官方 openid，并可将 `group_openid` 映射到 Linux 网页使用的数字群号。 |
| `scum_query` | 已实现 | `绑定id`、`解绑`、`查询在线`、`查询 关键词` 不需要斜杠，调用 Linux SCUM 中转。 |
| `statistics` | 已实现 | 签到、积分、排行和群统计，数据保存在 Linux SQLite。 |
| `auto_reply` | 已实现 | 添加、删除、查看和开关文字回复。 |
| `lottery` | 已实现 | 发起、报名、开奖和状态查询。 |
| `entertainment` | 已实现 | 骰子、猜拳、随机选择和时间。 |
| `user_replies` | 已实现 | 按群和用户 OpenID 保存专属关键词回复。 |
| `blacklist` | 已实现 | 调用官方群黑名单接口，并在本地保留记录。 |
| `moderation` | 已实现 | `/禁言`、`/解禁`、`/全体禁言`、`/全体解禁`、`/撤回用户`、`/撤回`、`/群禁言状态`、`/群成员` 和 `/成员信息` 调用官方接口。 |
| `keyword_mute` | 已实现 | 独立维护关键词禁言规则，命中后调用官方成员禁言接口。 |
| `keyword_kick` | 已实现 | 独立维护关键词踢出规则，命中后调用官方移除成员接口。 |
| `keyword_blacklist` | 已实现 | 独立维护关键词黑名单规则，命中后移出成员并调用官方黑名单接口。 |
| `group_info` | 受权限限制 | `/群信息`、`/群资料`、`/机器人群状态` 调用官方群信息接口；账号未获开放平台权限时会返回官方错误，不伪造数据。 |
| `join_approval` | 受权限限制 | `/入群申请`、`/同意入群`、`/拒绝入群`，以及后台的自动审批策略调用官方接口；是否开放由 QQ 官方账号权限决定。 |
| `group_admins` | 已实现 | 每个群独立维护分管管理员。 |
| `message_records` | 已实现 | 按群保存消息时间、成员和撤回状态；不保存正文。 |
| `scheduled_messages` | 已实现 | 按群设置重复间隔，由官方消息 API 主动发送。 |
| `song_request` | 已实现 | `/点歌 歌曲名` 返回歌曲搜索链接；不伪造失效音乐名片。 |
| `group_settings` | 已实现 | 网页独立设置群功能开关、SCUM、自动回复和消息记录。 |

所有可写数据都在 Linux 的 `JOKER_QQ_DATA_DIR` 下创建。部署脚本只复制程序，不复制 Windows 数据；Linux 网页或其他管理端若要修改这些数据，应使用同一数据目录或后续接入统一数据 API。当前项目不会自动读取 Windows 端 `sql/`、`data/` 或插件配置；官方群的 openid 与网页数字群号需要先手动映射。

群管命令默认允许主人、全局管理员、官方事件中的群主/群管理员和本群分管管理员执行；查询、自动回复、SCUM 等普通功能不要求发送人是管理员。官方平台还要求机器人具备群管理员权限；成员禁言、群成员和黑名单接口需要 QQ 开放平台实际向账号开放。

当前未把“入群欢迎”、音乐点歌、文转图等能力列入功能目录，也未接入消息处理器，因为当前 QQ 官方机器人项目没有对应的可靠官方事件或媒体服务。后台只显示已经接入本项目并有明确官方接口的功能。

关键词撤回不列入目录。官方机器人只能可靠撤回自身发送的消息，不能把群成员发出的普通消息当作可撤回目标。
